title: CI/CD pipeline with gates that block and a recorded rollback
oneLiner: "Eight PR gates feed one required ci-ok check; the demo page starts the gate run, ships a bad image, and redeploys the previous release."
stack:
  - GitHub Actions
  - Docker Buildx
  - Trivy
  - Fastify
  - PostgreSQL
claim: >-
  The release lane gates on five live smoke assertions: a build that misses one
  is rolled back to the previous release, and the hosted demo page records the
  order.
what: >-
  A Fastify invoice API on PostgreSQL 16 with a GitHub Actions workflow, a
  Dockerfile and a release script. The workflow defines eight gates and a ci-ok
  aggregator; the hosted demo page dispatches the gate run, the bad-image run
  and the rollback from a server-side token. The release lane swaps a current
  pointer, waits on /health and /ready, runs five smoke assertions and
  redeploys the previous release when an assertion misses.
hardPart: >-
  A process can answer /health and /ready while its invoice route returns
  errors, and a release with no return path leaves that process in front of
  traffic. The hard part is deciding the deploy on what the service does, not
  on what its health endpoint reports.
decision:
  title: Smoke decides the release; health starts the wait
  choice: >-
    After the health wait, run five smoke assertions and roll back when any
    assertion misses, then re-smoke the restored release.
  rejected: >-
    Treat /health and /ready as success; a process can answer both while its
    invoice route returns errors.
  cost: >-
    Every release pays for five assertions and a rollback restart, and rollback
    returns to the previous release.
  evidence: >-
    deploy.log records deploy.start, health.ok, smoke.fail, rollback.start,
    rollback.health.ok, rollback.smoke.ok.
failures:
  - summary: >-
      The process answers /health and /ready while the invoice route returns
      errors, or a release is promoted with no way back to the previous build.
    mechanism: >-
      The release lane swaps the current pointer, waits on /health and /ready,
      then runs five smoke assertions; any miss triggers rollback.start,
      restores the previous release, and re-runs the same smoke gate. deploy.log
      records every step.
