claim: >-
  Eight PR gates feed one required ci-ok check, and the local release lane
  rolled back a build with an injected 500 on POST /invoices after its smoke
  gate caught the failure; deploy.log records the order. Whether a red PR
  blocks a merge is not measured, because the repository has no remote.
problem: >-
  A workflow file can declare gates that have never run. This repository has no
  remote, the host has no Docker daemon, and a release lane without a rollback
  step can leave a broken process serving after a health check passes.
constraint: >-
  No GitHub Actions run exists, no registry credentials are present, and
  docker info fails with Access is denied. Windows excludes ports 8001 to 8300
  on this host, so the service runs on 127.0.0.1:8787 and there is no public
  URL.
architecture: >-
  pr.yml runs eight jobs and a ci-ok aggregator that needs all eight, with
  every action pinned to a commit SHA. The local lane builds a release, swaps
  the current pointer, restarts the process, waits for /health and /ready, runs
  five smoke assertions, and rolls back to the previous release when smoke
  fails. deploy.log is the ordered evidence; a screenshot is not.
decisions:
  - title: One ci-ok aggregator instead of eight required checks
    choice: >-
      Require a single ci-ok job that lists all eight gate jobs in needs, so
      branch protection points at one name that cannot drift from the workflow.
    rejected: >-
      Require every gate individually in the repository settings. Adding or
      renaming a gate then needs a settings change outside the repository, and
      the required list can silently omit a job.
    cost: >-
      ci-ok must fail when a needed job fails or is skipped, and the ruleset
      that makes ci-ok required lives on GitHub, where this repository cannot
      verify it.
    evidence: >-
      The structural check lists 9 jobs including ci-ok and 0 unpinned uses;
      docs/evidence/workflow-structure.txt is in the snapshot.
  - title: Smoke failure rolls back; health alone is not a deploy gate
    choice: >-
      After the health wait, run five smoke assertions and roll back to the
      previous release when any assertion fails, then re-wait and re-smoke the
      restored release.
    rejected: >-
      Treat a healthy /health and /ready response as success. The injected
      invoices-500 build stayed healthy while its POST /invoices returned 500,
      so a health-only gate would have left it serving.
    cost: >-
      Every release pays for five live assertions and a restart on rollback,
      and rollback is valid only one release back and only for
      expand/contract migrations.
    evidence: >-
      deploy.log records deploy.start, health.ok, smoke.fail, rollback.start,
      rollback.health.ok and rollback.smoke.ok in file order; the rollback
      timeline is shot-01.
  - title: Record the negative result instead of simulating the CI lane
    choice: >-
      Commit docker-info.txt showing Access is denied, and mark the image
      build, Trivy scan, cosign signature and attestation as unverified in the
      manifest limits.
    rejected: >-
      Render a green check page from the workflow YAML and present it as a run.
      That is the exact failure this project is about: a mock is not evidence.
    cost: >-
      The CI lane remains unexecuted, so the repository cannot claim that the
      image was built, scanned, signed or pushed.
    evidence: >-
      docs/evidence/docker-info.txt records the daemon failure, and the hero
      image is labelled a mock in its alt text.
