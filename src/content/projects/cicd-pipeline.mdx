title: CI/CD pipeline with gates that block and a recorded rollback
oneLiner: "Eight PR gates feed one required ci-ok check; the local release lane builds, swaps, waits for health, proves five smoke assertions, and records a rollback."
stack:
  - GitHub Actions
  - Docker Buildx
  - Trivy
  - cosign
  - Fastify
  - PostgreSQL
updatedAt: "2026-10-24"
claim: >-
  The release lane gates on five live smoke assertions: a build that misses one
  is rolled back to the previous release, and deploy.log records the order.
what: >-
  A Fastify invoice API on PostgreSQL 16 with a GitHub Actions workflow, a
  Dockerfile and a local release script. The workflow defines eight gates and
  a ci-ok aggregator; the release script swaps a current pointer, waits on
  /health and /ready, runs five smoke assertions and rolls back to the previous
  release when an assertion misses.
hardPart: >-
  A process can answer /health and /ready while its invoice route returns
  errors, and a release with no return path leaves that process in front of
  traffic. The hard part is deciding the deploy on what the service does, not
  on what its health endpoint reports.
decision:
  title: Smoke decides the release; health starts the wait
  choice: >-
    After the health wait, run five smoke assertions and roll back when any
    assertion misses, then re-smoke the restored release.
  rejected: >-
    Treat healthy /health and /ready responses as success; a process can answer
    both while its invoice route returns errors.
  cost: >-
    Every release pays for five live assertions and a rollback restart, and
    rollback returns to the previous release.
  evidence: >-
    deploy.log records deploy.start, health.ok, smoke.fail, rollback.start,
    rollback.health.ok, rollback.smoke.ok.
failures:
  - summary: >-
      The process answers /health and /ready while the invoice route returns
      errors, or a release is promoted with no way back to the previous build.
    mechanism: >-
      The release lane swaps the current pointer, waits on /health and /ready,
      then runs five smoke assertions against the live service; any miss
      triggers rollback.start, restores the previous release, and re-runs the
      same smoke gate. deploy.log records every step in order.
measured: >-
  The local lane is measured: nine integration tests passed, the smoke gate
  passed five of five assertions with /ready p95 7.7 ms, and deploy.log records
  the rollback order. The workflow structure check found eight gates feeding
  ci-ok and zero unpinned actions. The workflow is the source of the gate
  topology; the local lane is the source of the runtime evidence.
